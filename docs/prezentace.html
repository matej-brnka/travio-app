Idea

Cílový uživatel: cestovatel mladší generace, který chce přehledně naplánované místa v dané destinaci — bez žonglování se zápisníky, tabulkami nebo generickými poznámkovými bloky.

📍 Uživatel zadá destinaci + termín
↓
📅 Aplikace automaticky vygeneruje strukturu dnů
↓
🗺️ Uživatel přidává místa, řadí je, označuje jako navštívená
↓
🤖 Volitelně: AI sestaví kostru itineráře
↓
🔗 Sdílení anonymním odkazem (read-only, jako Google Drive)

RAG & MCP

RAG – aktuální stav

V MVP není – AI funguje jako zero-shot / few-shot promptování bez vektorové DB.

Přirozené rozšíření: DB recenzí + lokálních tipů + uživatelských itinerářů jako znalostní báze pro personalizovaná doporučení.

MCP – aktuální stav

V projektu není implementováno.

Potenciální use case: MCP server s nástroji
search_places · get_weather · get_trip_context
→ LLM autonomně sestaví itinerář bez hardcoded API orchestrace.

Autonomous Agent

V MVP funguje AI jako single-turn generátor – obdrží kontext, vygeneruje itinerář, uloží výsledek.

Zárodky agentní architektury:

  • Backend orchestruje více kroků: vytvoření cesty → generování dnů → volání AI → uložení míst
  • POST /api/trips/:id/ai-generate – re-generace pro existující cestu (opakované volání)
  • Admin monitoring všech AI akcí = audit trail
Plnohodnotný agent (vícekrokový, s memory a tool use) = přirozený krok pro roadmapu

Top Challenges

1 · Typová bezpečnost přes celý stack

PostgreSQL DATE sloupce → pg driver parsuje jako JS Date s lokální půlnocí → timezone bug.

Řešení: types.setTypeParser(1082, val => val)
DATE přichází jako plain string, bez konverze.

2 · Invite-only registrace bez custom auth serveru

Closed beta – nové účty povoleny pouze pro e-maily ve whitelist tabulce.

Implementováno přes Supabase before-user-created Auth Hook (Postgres funkce).
Frontend dělá pre-check před Google OAuth flow.

Interesting Facts

  • Mapa jako primární UI – Google Maps fullscreen, itinerář je sekundární vrstva (horizontální strip karet dole na mobilu)
  • Klik na nativní Google POI přímo přidá místo do itineráře – bez hledání
  • Duplicita míst detekována přes googlePlaceId – aplikace se zeptá před přidáním podruhé
  • Admin cost dashboard – reálné náklady Google Places (dle SKU) i OpenAI tokenů + e-mail uživatele pro audit
  • Share link bez přihlášení – stejný pattern jako Google Drive
  • Frontend vygenerován v Lovable (AI-assisted prototyping), backend postaven ručně v NestJS
